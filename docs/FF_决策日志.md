# 为什么放弃了自定义标题栏，而是采用修改了颜色的原生标题栏？

为了回答这个问题，首先需要分析一下我参考的其他软件是如何处理自定义标题栏的：

**VSCode**： 合并了标题栏和菜单栏，但 VSCode 的菜单栏实际上是低频访问的，合并在一起可以有效节省空间。*而我们可能并没有菜单栏，所以……*

**Edge、文件资源管理器**： Edge 和 文件资源管理器都是把标题栏和标签页合并了，因为实际上这里的”标签页“就只是合并了窗口，而不是 dock。一个标签页实际上就是一个功能完整的窗口。*所以从这个角度，也和我的设计不太一样，我们功能的最小单位是 dock，而不是窗口*

**Obsidian**： Obsidian 实际上有左中右三个主要的区域，这看起来更像是把区域的工具栏放到上面了，仔细看的话还能看到标题栏被分割成了三部分。*而我的 dock 的工具栏应该在dock里，因为不知道插件会提供什么样的工具栏.*

**IlinaGUI 的上一个版本**：这个版本实际上只在标题栏上添加了一个指示状态的东西，但现在，这个东西应该放在dock里而不是dock外面，之后标题栏就只剩下标题和三个按钮了。

**Steam**：我觉得和 VScode 有点像，也是把低频菜单栏合并了，然后还加了通知、头像什么的，我没有这些功能，所以无所谓。

**QQ**：额外添加了：1. 头像和个签，这个当然我不需要 2. 天气：其实我不知道为什么会出现在这里 3. ”切换为经典模式“ 这个会切换 QQ 主面板的风格，不过这个差不多是 QQ 的专属功能了

**微信**：多了一个”固定最前“的钉子，甚至去掉了窗口图标和名称

分析之后，得出的结论就是：当前的 IlinaGUI 并不需要自定义标题栏，有原生的标题栏就足够用了，而至于 ”标题栏和窗口内容在观感上有明显差距“ 的问题，可以通过将标题栏颜色设置为窗口背景色来解决，这样在视觉上就完全一致。

另外，这种操作还具有以下的好处：
1. 100% 的窗口功能，因为它就是原生标题栏，拖动、缩放和双击等操作由系统实现，QtAds 也能完美适配。
2. 由于不需要实现窗口功能，所以可以移除非常多的代码，也无需自己实现标题栏。
3. 使用原生标题栏，保证了在 mac 和 linux 上可用，虽然还没处理其他平台上的外观，但兼容性不用担心

综上所述，决定改为使用**原生窗口标志+修改标题栏颜色**的方法
